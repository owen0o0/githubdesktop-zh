Guide

帮助

本工具在浏览器内完成字符串替换，文件不会上传到服务器。汉化后需把 main.js / renderer.js 覆盖回 GitHub Desktop 安装目录。

通用步骤

  1. 完全退出 GitHub Desktop（确保进程已结束）。
  2. 按下方平台说明找到安装目录中的 main.js 与 renderer.js。
  3. 打开本站「汉化」页，上传这两个文件，点击「开始汉化」。
  4. 下载结果（可单独下载，或点「下载 ZIP」一次打包），覆盖回原路径。 建议先备份原文件。
  5. 按平台说明完成收尾（如 macOS 重签），再启动 GitHub Desktop。

请先在汉化页选择与本机一致的平台（macOS / Windows / Linux）。三套词典字面量不同（大小写、菜单 &、Finder/Explorer 等），选错会明显漏译。 Desktop 自动更新后会生成新的 app-x.y.z 目录，汉化会失效，需对新区再汉化一次。

各平台说明

安装目录

/Applications/GitHub Desktop.app/Contents/Resources/app/

其中应能看到 main.js、renderer.js、index.html 等文件。

覆盖后必须重签

否则可能无法启动或被 Gatekeeper 拦截。在「终端」执行：

codesign --force --deep --sign - "/Applications/GitHub Desktop.app"
xattr -cr "/Applications/GitHub Desktop.app"

权限提示

  • 若无法写入，先把文件复制到桌面汉化，再拖回原目录（需输入管理员密码）。
  • 也可：右键应用 →「显示包内容」→ 进入上述路径后替换。

安装目录

通常在用户本地应用数据目录（版本号会变）：

%LOCALAPPDATA%\GitHubDesktop\app-<版本号>\resources\app\

在资源管理器地址栏粘贴下面路径并回车，进入后选择最新的 app-* 文件夹：

%LOCALAPPDATA%\GitHubDesktop

操作建议

  • 先完全退出 GitHub Desktop（托盘图标也要退出）。
  • 覆盖前复制一份 main.js / renderer.js 备份。
  • 若提示文件占用，在任务管理器结束所有 GitHubDesktop.exe 后再试。
  • 覆盖后直接重新打开即可，一般无需额外签名。

注意

Squirrel 更新后会出现新的 app-x.y.z 目录，旧目录里的汉化不会自动带过去，需对新目录再操作一次。

常见安装路径

因发行渠道不同，路径可能不一样，优先检查：

/opt/github-desktop/resources/app/
/usr/lib/github-desktop/resources/app/
/usr/share/github-desktop/resources/app/

也可以用命令定位：

which github-desktop
# 或
find /opt /usr -name 'renderer.js' 2>/dev/null | grep -i github

覆盖权限

  • 系统目录通常需要 sudo 复制回去。
  • 覆盖前请备份原文件。
  • 完成后重新启动 github-desktop。

Flatpak / 其他封装

若通过 Flatpak 等封装安装，应用文件在沙箱目录内，路径更长且更新会重置。建议优先使用官方或社区 deb/rpm 包后再汉化。

常见问题

要不要按 GitHub Desktop 版本选词典？
不同版本的 main.js / renderer.js 确实会增减文案，但目前每平台只维护一份「当前主线」词典。 版本跨度大时可能漏译或偶发未命中；优先保证平台选对。若以后要做版本矩阵，会按 dict/<平台>/<版本>.zh + 清单文件管理，而不是把所有历史版本都塞进下拉框。
启动后界面仍是英文 / 大量未翻译？
词典与 Desktop 版本可能不匹配。可到「词典」页核对条目，或等词典更新后再汉化。
设置页（如 Copilot）空白？
本工具会跳过 return / case 等状态字面量。若仍异常，请用备份还原，并检查是否手工改过词典中的控制流字符串。
macOS 提示已损坏 / 无法打开？
确认已执行 codesign 与 xattr -cr，并完全退出后再启动。
文件会上传到服务器吗？
不会。汉化在本地浏览器完成；「词典编辑」才与本机服务通信，且只读写词典文件。

需要改词条？见「词典」与「编辑」页。编辑需密码（见项目 .env）。
